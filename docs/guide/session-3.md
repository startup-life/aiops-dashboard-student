# 3회차 보충 문서: 강사 API 연결과 과거 조회

> 이 문서는 3회차 프롬프트가 만드는 내용의 자세한 약속입니다. 앞 회차 문서에 이어지며, 앞 문서와 다르면 이 문서를 따릅니다.

## 이 문서를 읽는 법

- 백틱 안의 글은 이름이나 값입니다. 글자 그대로 씁니다.
- 큰따옴표 안의 글은 화면에 나오는 글자이거나 코드에 들어가는 값입니다. 한 글자도 바꾸지 않습니다. 단, 프롬프트 마지막 참고 줄의 큰따옴표 안은 이 문서의 절 제목입니다.
- "쓰는 단계"는 그 내용을 만드는 프롬프트 번호입니다. 프롬프트 맨 앞의 `[2-14]` 같은 표시가 이번 단계입니다. 그 번호가 "쓰는 단계"나 줄 앞에 적힌 내용만 만들고, 다른 번호의 내용은 그 프롬프트를 받기 전에 만들지 않습니다.
- "만들지 않는 것" 절에 적힌 기능은 완료 브랜치 코드에 있어도 만들지 않습니다.
- 창고 쪽 이름은 공장 쪽 이름의 `factory`를 `warehouse`로 바꾼 같은 이름입니다.

## 이 회차에서 만드는 것

- 시작 상태: 2회차가 끝난 화면입니다. 숫자·그래프·기록 표를 예시 자료로 채우고 주소별 화면, 알림 목록, 도움말이 동작합니다.
- 끝 상태: 화면이 강사 API의 실제 값으로 채워지고 10초마다 다시 조회합니다. 조회가 실패해도 이전 값이 남고 노란 안내로 이유를 알립니다. 헤더에서 과거 시각을 골라 그때의 자료를 보고, 조회 기록 화면에서 이 탭이 보낸 요청을 막대와 표로 봅니다. 예시 자료 파일은 없어집니다.
- 이번에 건드리지 않는 곳: 화면 파일(`public` 폴더)만 고칩니다. `public/assets/approved`의 사진과 `API_CONTRACT.md`는 그대로 둡니다. 강사 API는 읽기만 합니다.
- 두 가지 기록을 구별합니다. 기록 화면의 기록은 강사 API가 주는 현장 기록이고 조회 기록은 이 탭이 강사 API에 보낸 요청의 기록입니다.
- 약속 줄 앞의 굵은 번호는 그 줄을 만드는 프롬프트 번호입니다.
- "통째로 새로 그려도 되는 곳"은 2회차 문서의 말입니다. "지금"과 "오늘"은 줄마다 그 줄에 적힌 시각을 따릅니다.

## 앞 회차에서 바뀌는 것

- 2회차의 예시 자료(`public/sample-data.js`)는 3-3과 3-9에서 강사 API 자료로 바뀌고 3-12에서 지웁니다. 그때 `index.html`에서 그 파일을 부르는 줄도 지웁니다.
- 2회차 기록 화면의 기본값과 범위는 예시 자료의 "지금"을 기준으로 했습니다. 3-25부터 기준 시각을 기준으로 합니다.
- 2회차의 "통째로 새로 그려도 되는 곳"에 현장 사진 칸을 더합니다('현장 사진' 절).

## 연결 설정과 요청

쓰는 단계: 3-2, 3-3, 3-9, 3-18

연결 설정을 파일 하나로 나누어 뒤 회차에서는 이 두 값만 바꿉니다. 5회차의 GAS 웹 앱 주소가 `/exec`로 끝나므로 요청 주소를 만드는 규칙이 두 갈래입니다. 기록 요청은 3-9에서 처음 보내고, 시각을 붙인 `snapshot` 요청은 3-18에서 처음 보냅니다.

### 연결 설정 파일

- **3-2** 연결 설정은 `public/config.js`의 아래 네 줄입니다.

```js
window.DASHBOARD_CONFIG = {
  apiBaseUrl: "주소",
  timeoutMs: 5000
};
```

- **3-2** 키 이름·큰따옴표·줄 모양을 바꾸지 말고 다른 키를 넣지 않습니다. 뒤 회차에서는 이 두 값만 바뀝니다.
- **3-2** `apiBaseUrl`은 `API_CONTRACT.md` 9절 1단계 주소를 끝에 `/` 없이 씁니다.
- **3-2** `index.html`에서 `config.js`를 `app.js`보다 먼저 defer로 부르고, 설정은 페이지를 열 때 한 번 읽습니다(`window.DASHBOARD_CONFIG`, 없으면 빈 객체).

### 요청 주소 만들기

- **3-3** 주소 끝 `/` 하나를 뗀 뒤 아래 표대로 잇습니다. 쿼리는 `URLSearchParams`로 만듭니다.

| 주소 | 쿼리가 없을 때 | 쿼리가 있을 때 |
|---|---|---|
| `/exec`로 끝날 때 | 주소 + "?path=" + 경로 | 주소 + "?path=" + 경로 + "&" + 쿼리 |
| 그 밖 | 주소 + 경로 | 주소 + 경로 + "?" + 쿼리 |

### 보내는 요청

- **3-3, 3-9, 3-18** 요청은 두 가지입니다(`API_CONTRACT.md` 1·3절). 시각 쿼리는 `toISOString()` 글자입니다.

| 요청 | 쿼리 |
|---|---|
| `GET /api/v1/snapshot` | 과거 시각이면 `at` |
| `GET /api/v1/records` | `kind`(`production` 또는 `shipment`), `at`(마지막 `snapshot`의 `viewTime`), `from`·`to`(고른 때만) |

### 받기

- **3-3** 페이지를 열 때 강사 API에서 오늘 운영 자료를 한 번 받아 예시 자료 대신 오늘 운영 화면을 채웁니다. 다시 조회하는 일(10초 조회, 새로고침 버튼)은 3-5에서 만듭니다.
- **3-3** `apiBaseUrl`이 `http://` 또는 `https://`로 시작하지 않으면 요청하지 않고 실패로 봅니다.
- **3-3** 받을 때는 `fetch` `GET`, `cache` "no-store", 헤더 `Accept: application/json`을 씁니다.
- **3-3** `timeoutMs`(숫자가 아니면 `5000`)가 지나면 `AbortController`로 멈추고, 타이머는 성공·실패 모두 `finally`에서 지웁니다.
- **3-3** 받은 `snapshot`에 `viewTime`이 없으면 `serverTime`을 기준 시각("지금")으로 씁니다. 받은 자료를 다듬는 단계가 생기기 전, 처음 API 자료로 화면을 채울 때부터 이렇게 합니다.
- **3-3** 조회 상태를 보이는 단계(3-6, 3-7) 전까지 실패는 화면에 보이지 않습니다. 확인용 콘솔 출력(`console.error`, `console.log` 등)은 넣지 않습니다(완료 브랜치 코드에도 없습니다).

| 쓰는 단계 | 언제 | 글자 |
|---|---|---|
| 3-3 | 연결 주소가 잘못되었을 때 실패 문장 | "API 연결 주소가 설정되지 않았습니다." |

## 자료 다듬기

쓰는 단계: 3-3

받은 자료 가운데 틀린 칸만 비우고 나머지는 그대로 화면에 씁니다. 자료 검사는 3-15에서 만듭니다. 그 전에는 받은 자료를 바로 이 규칙으로 다듬습니다.

### 약속

검사를 통과한 `snapshot`은 틀린 칸만 비웁니다. 칸마다 아래 규칙을 씁니다.

| 칸 | 규칙 |
|---|---|
| `viewTime` | 없으면 `serverTime` |
| `target`·`completed` | 0 이상 정수가 아니면 `null` |
| `status` | `normal`·`warning`·`error` 밖이면 `unknown` |
| `note` | 글자가 아니면 "기록 대기" |
| `processingState` | `completed`·`paused`·`waiting` 밖이면 `processedAt`이 있을 때 `completed` 아니면 `waiting` |
| `lastEventAt`·`receivedAt`·`processedAt` | 시각이 아니거나 `viewTime`보다 늦으면 `null` |
| `image` | `url`·`alt`가 모두 글자일 때만 |
| `history` | 배열이고 24개 이하이며 모든 점이 맞을 때만 시각 순으로(하나라도 틀리면 그 현장만 빈 배열) |
| 알림 `status` | `sent`·`failed` 밖이면 `unknown` |

## 응답 전 화면

쓰는 단계: 3-4

응답이 오기 전의 오늘 운영 화면입니다. 값이 없다는 것을 글자로 보여 주고, 스크립트가 돌기 전에도 같은 글자가 보이게 합니다.

### 약속

- 응답 전(자료도 오류도 없음)에는 숫자 대신 "조회 중" 글자를 보이고 0을 보이지 않습니다. 자료가 없을 때 화면을 다시 그려도 응답 전 글자가 그대로 나오게 합니다.
- 배지에 `loading`을 주면 `neutral` "조회 중"입니다.
- 응답 전에는 id `page-content`에 `aria-busy="true"`를 두고, 자료나 오류가 생기면 `aria-busy="false"`로 바꿉니다(속성을 지우지 않음).
- 생산·출고 카드의 수량은 "조회 중"만 쓰고 목표 글은 비우고 진행 막대는 숨깁니다.
- 카드의 사진 칸은 그대로 두고 그 안에 사진과 사진 설명 대신 "현장 사진 확인 중" 글자만 보이게 합니다. 자료가 온 뒤에도 3-8을 만들기 전까지 사진 칸은 "현장 사진 확인 중" 글자로 둡니다.
- `index.html`의 처음 글자도 아래 표의 글자로 바꿔, 스크립트가 돌기 전에 1회차 고정 글자와 숫자가 보이지 않게 합니다.

## 조회 방식

쓰는 단계: 3-5

조회가 겹치지 않고 예약이 늘 하나이도록 조회를 함수 하나로 모읍니다. 3-5에서 함수 하나, 조회 중 막기, 새로고침 버튼, 10초 예약과 남은 초를 함께 만듭니다.

### 조회 함수와 예약

- **3-5** 조회는 페이지를 열 때의 첫 조회까지 함수 하나(`poll`)로 합니다. 조회 중이면 새로 보내지 않습니다.
- **3-5** 응답이 온 뒤(성공·실패 모두) 10초 뒤 조회를 예약합니다. 예약은 늘 하나이고, 새로고침 버튼은 예약을 지우고 바로 조회합니다.
- **3-5** 다음 조회까지의 초는 0.25초마다 글자만 고칩니다.
- **3-5** 예약 시각이 이미 지났거나, 탭이 다시 보일 때(`visibilitychange`) 예약 시각이 지났으면 바로 조회합니다.
- **3-5** 다음 조회 글자(id `countdown-text`)는 `min-width` `88px`로 폭을 고정해, 글자가 "조회 중…"으로 바뀌어도 머리 부분이 움직이지 않게 합니다.

### 새로고침 버튼

헤더의 새로고침 버튼으로 다시 조회하게 만들 때 이어지는 네 줄을 함께 만듭니다.

- **3-5** 조회 중 새로고침 버튼은 `disabled` 대신 `aria-disabled="true"`·`aria-busy="true"`를 두고 class `loading`을 붙입니다. 버튼을 키보드로 누른 뒤에도 초점이 버튼에 남게 하기 위해서입니다.
- **3-5** 조회 중에는 새로고침 아이콘이 1초에 한 바퀴 돕니다.
- **3-5** 조회가 끝나면 두 속성을 "false"로 바꾸고(지우지 않음) class `loading`을 뗍니다.
- **3-5** 버튼에 초점을 두고 Enter를 누르고 있어도 요청이 이어지지 않게, 되풀이되는 Enter(`event.repeat`)는 막습니다.

| 3-5 | 조회 중이거나 다음 조회가 정해지지 않았을 때 | "조회 중…" |

## 조회 상태 보이기

쓰는 단계: 3-6, 3-7

지금 조회가 어떤 상태인지 헤더와 본문 위에 보입니다. 노란 안내 상자는 3-6에서 자리만 만들고 3-7부터 씁니다.

### 약속

- **3-6** 조회 상태는 마지막 성공 자료, 마지막 성공 시각, 지금 오류 문장 셋으로 둡니다.
- **3-6** 조회 정보 줄은 `main` 맨 앞(본문 `section` 위)의 두 칸입니다: 마지막 조회 시각(id `updated-at`), 기준 시각 안내(id `view-context`). 앞 칸에 글이 있으면 그 뒤에 쉼표를 붙입니다. 조회 정보 줄은 작은 회색 글자입니다.
- **3-6** 노란 실패 안내는 id `data-errors`입니다. 주소 안내("요청한 주소의 화면이 없어 오늘 운영으로 이동했습니다.") 바로 아래에 두고 처음에는 숨깁니다.
- **3-7** 조회가 실패하면 노란 실패 안내를 보이고, 성공하면 숨깁니다.
- **3-7** 실패해도 마지막 성공 자료는 지우지 않고 화면에 남깁니다.

## 현장 사진

쓰는 단계: 3-8

카드 사진을 받은 자료의 사진 주소로 보여 줍니다.

### 약속

- 현장 사진은 `snapshot`의 `sites.(현장).image.url`을 고치지 않고 `img`의 `src`에 씁니다.
- 주소와 `alt`가 지난번과 같으면 다시 만들지 않습니다. 10초 조회 때 사진이 깜박이지 않게 하기 위해서입니다.

## 기록 화면

### 기록 받기

- **3-9** 기록 화면에 있으면 `snapshot` 조회가 성공할 때마다 기록도 따로 받고, 기록 화면으로 들어오면 조회 중이 아닐 때 바로 조회합니다.
- **3-9** 기록 요청에도 처음부터 번호를 매겨, 다른 화면으로 옮기거나 "시간대 조회"를 누르기 전에 보낸 기록 요청의 응답은 늦게 와도 버립니다.
- **3-9** 같은 화면의 기록 요청이 아직 진행 중이면 다음 조회는 새 기록 요청을 보내지 않고 그 응답을 기다립니다. 번호가 바뀌면(화면 이동, 시간대 조회, 기준 시각 변경) 새로 보냅니다.

### 표 자리에 보이는 안내

글자는 이 절의 "화면 글자" 표에 있습니다.

- **3-9** 기록을 받기 전에는 표 자리에 "기록을 확인하고 있습니다."를 보입니다. 기록 요청이 실패하면 노란 안내로 오류 문장을 보입니다.
- **3-9** 오늘 운영 자료를 받지 못해 기록 요청을 못 보냈고 보여 줄 기록도 없으면 표 자리에 노란 안내로 화면 글자 표의 '오늘 운영 자료를 받지 못했을 때' 글자를 보입니다. 앞서 받은 기록이 있으면 그 표를 그대로 둡니다.
- **3-9** 첫 조회 응답을 기다리는 동안(자료도 오류도 없음)에는 표 자리에 회색 "기록을 확인하고 있습니다."를 보입니다. 노란 안내는 조회가 실패한 뒤에만 보입니다. 조회 상태 변수는 페이지를 열 때의 첫 그리기보다 앞에 선언합니다.

### 시간대 조회

- **3-10** "시간대 조회"를 누르면 앞서 받은 표를 비워, 새 응답을 기다리는 동안 표 자리에 기록을 받기 전 안내가 보이게 합니다(이 동작은 그 버튼을 만들 때 함께 넣습니다).
- **3-10** `from`·`to`는 "시간대 조회"를 누른 값만 보냅니다(칸 글자 + "+09:00"을 `toISOString()`).
- **3-10** 칸만 고치고 누르지 않은 값은 요청에 쓰지 않습니다. 조회 중에 눌러도 막지 말고, 진행 중인 조회가 끝나면 새 시간대로 받습니다.

### 시작·종료 칸의 값

- **3-3** 기록 화면을 주소로 바로 열어 자료가 아직 없을 때도 오류 없이 그립니다. 이때 시작·종료 칸의 기본값과 고를 수 있는 범위는 브라우저 시계로 오늘 00:00:00부터 지금까지입니다.
- **3-10, 3-25** 칸에 보일 값은 사용자가 고친 값, 없으면 "시간대 조회"로 기억한 값, 없으면 기본값(기준 시각 날짜의 00:00:00, 기준 시각)입니다.
- **3-25** 칸에서 고를 수 있는 범위도 기준 시각 날짜의 00:00:00부터 기준 시각까지입니다. 그 범위에 기록이 없어도 가짜 기록을 만들지 않습니다.
- **3-10, 3-25** 초점이 있는 칸은 덮어쓰지 않습니다.
- **3-10, 3-25** 기준 시각은 마지막 `snapshot`의 `viewTime`, 없으면 고른 과거 시각, 없으면 브라우저 시계입니다.
- **3-10** 고치지 않은 칸은 조회할 때마다 기본값을 따라갑니다.

### 같은 기록이면 표 그대로

- **3-11** 10초 조회로 받은 기록이 지난번과 같으면 표를 다시 만들지 않습니다.
- **3-11** 달라서 다시 그릴 때는 표의 가로 스크롤 위치와 초점을 지킵니다. 2회차 문서 '키보드·초점·스크롤 지키기'의 방식이 10초 조회에도 그대로 동작하면 모자란 곳만 고칩니다.

### 다른 화면으로 옮길 때

- **3-10** 다른 화면으로 옮길 때마다(생산 기록 화면과 출고 기록 화면 사이도) 고른 시간대, 고친 칸 값, 받은 기록과 기록 오류를 비웁니다.

- **3-18** 새로고침 버튼은 같은 시각으로 조회합니다.
- **3-18** 과거 시각 요청이면 응답 `viewTime`이 `at`과 같은 시각이어야 합니다.
- **3-18** 기준 시각을 바꾸면 예약한 다음 조회를 지우고, 이전 자료·성공 시각·오류·받아 둔 기록·고른 시간대·고친 칸 값을 비운 뒤 바로 조회합니다.

### 시각이나 주소가 바뀔 때

기준 시각을 바꾸는 기능을 만들 때 아래 세 줄을 함께 만듭니다.

- **3-18** 기준 시각이나 화면 주소가 바뀔 때마다 번호를 올리고, 번호가 바뀐 뒤 도착한 응답은 성공·실패 모두 화면에 쓰지 않고 버립니다.
- **3-18** 시각을 바꾸면 이전 자료·성공 시각·오류·기록·고른 시간대를 비웁니다.
- **3-18** 조회 중에 시각이나 주소가 바뀌면 새 요청은 바로 보내지 않고, 진행 중인 조회가 끝나자마자 10초를 기다리지 않고 새 시각(주소만 바뀌었으면 같은 시각)으로 다시 조회합니다.

### 안내와 "현재로 돌아가기" 버튼

- **3-19** 기준 시각 안내 id `view-context`, 현재로 돌아가기 버튼 class `inline-button`, 노란 실패 안내 id `data-errors`입니다.
- **3-19** "현재로 돌아가기"를 누르면 기준 시각을 "현재"로 바꾸고 자동 조회를 다시 시작합니다.
- **3-19** "현재로 돌아가기"를 눌러도 열린 알림 목록은 닫히지 않습니다.
- **3-19** 바깥 클릭 처리에서 눌린 요소가 그 버튼인지는 `event.target.closest`로 찾고, 문서에 아직 있는지(`contains`)나 위치로 판단하지 않습니다(버튼이 누르는 순간 다시 그려져 문서에서 떨어지기 때문).

## 조회 기록

쓰는 단계: 3-20

조회 기록은 이 탭이 보낸 요청을 남깁니다. 탭마다 따로 남습니다.

### 약속

- **3-20** 조회 기록은 `poll` 한 번마다 한 건입니다: `requestedAt`(요청 시작, ISO), `at`(현재면 ""), `ok`, `durationMs`(정수), `available { factory, warehouse }`(그 현장 `completed`와 `target`이 둘 다 0 이상 정수면 `true`), `error`(실패 문장의 첫 문장. ". "까지 자르고 60자가 넘으면 60자 + "…"). 버린 응답도 남깁니다.
- **3-20** 조회 기록은 최근 200건만 `sessionStorage`의 "tumble-query-log"에 JSON 배열로 저장하고, 페이지를 열 때 모양이 맞는 항목만 읽어 옵니다.
- **3-20** 읽거나 쓰지 못하면 메모리의 배열로 이어 갑니다.
- **3-20** 페이지를 떠나는 중(`beforeunload`·`pagehide`에서 켜고, `timeoutMs` 뒤나 `pageshow`에서 끔)에 실패한 조회는 오류로 쓰지 않고 기록에도 남기지 않습니다.
- **3-20** `beforeunload`에서 확인 창을 띄우지 않습니다.

## 조회 기록 화면

쓰는 단계: 3-22, 3-23, 3-24

조회 한 번을 막대 하나로 보여 주고, 그 아래에 성공률과 최신순 표를 둡니다. 막대 색은 결과 색과 같습니다. 글자는 이 절의 "화면 글자" 표에 있습니다.

### 맨 위 카드

- **3-22** 제목과 마지막 조회 결과, 조회 기록이 없을 때의 글을 아래 표의 3-22 줄대로 둡니다.

### 막대 줄

- **3-22** 막대(`button`, class `history-bar`, `data-at`에 `requestedAt`)는 오래된 것부터 놓습니다.
- **3-22** 막대에 마우스를 올리면 그 조회의 시각·결과·응답시간·기준 시각이 담긴 막대 글이 뜨고, 같은 글을 화면 읽기 글에도 씁니다. 과거 시각 조회였으면 "현재" 자리에 그 기준 시각을 같은 날짜 꼴로 씁니다.
- **3-22** 막대는 폭이 좁은 세로 막대(높이 약 64px)로 가로로 늘어서고, 넘치면 옆으로 밀어 봅니다. 막대에 키보드 초점이 가면 테두리가 보입니다.

### 막대 아래 글

- **3-23** 고른 막대 글은 class `history-detail`, 성공률 줄은 class `history-range`(굵은 성공률 글은 그 안 `strong`)입니다.
- **3-23** 막대를 누를 때마다(이미 고른 막대를 Enter로 다시 눌러도), 그리고 막대에 키보드 초점이 갈 때마다 `history-detail` 글을 그 막대 글로 다시 씁니다.
- **3-23** 막대 줄 아래에 첫 기록 시각, 굵은 성공률 글, 마지막 기록 시각을 한 줄로 둡니다. 성공률 줄은 양 끝에 맞춘 작은 회색 글입니다.

### 조회 기록 표

- **3-23** 표는 최신부터입니다(기록 표처럼 class `table-scroll` 안, 머리글 `thead`, 줄 `tbody`).

### 다시 그릴 때

- **3-24** 다시 그릴 때 누르거나 초점을 둔 막대를 기억해, 아래 글은 그 막대의 글로 두고 초점도 같은 막대에 남게 합니다. 화면 주소가 바뀌면 고른 막대를 잊습니다.
- **3-24** 다시 그릴 때 막대 줄과 조회 기록 표의 가로 스크롤 위치도 지킵니다. 화면 주소가 바뀐 뒤 처음 그릴 때는 위치를 지키지 않습니다.

## 사용자가 직접 하는 일

AI 도구는 아래 일을 하지 않습니다.

- 서버 켜기와 끄기(`npm.cmd start`). 이번 회차는 화면 파일만 고치므로 켜 둔 채로 두고 브라우저만 새로고침합니다.
- 실패 화면을 보려고 `public\config.js`의 `apiBaseUrl`을 잠시 바꾸고 되돌리는 일.
- Network 탭의 속도 바꾸기, 브라우저에서 화면과 요청을 확인하는 일.
- 회차 끝에 커밋하기(`git add`, `git commit`).

강사 API의 상황은 강사가 바꿉니다. 수강생은 읽기만 합니다.

실패 화면을 보는 시험(`config.js`를 잠시 바꾸기, Network 탭의 "오프라인")은 3-17에서 사용자가 따라하기 안내대로 합니다. AI 도구는 답에서 설정 값이나 Network 탭을 바꿔 시험해 보라고 안내하지 않습니다.
