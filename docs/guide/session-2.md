# 2회차 보충 문서: 예시 자료로 화면 채우기와 화면 주소

> 이 문서는 2회차 프롬프트가 만드는 내용의 자세한 약속입니다. 앞 회차 문서에 이어지며, 앞 문서와 다르면 이 문서를 따릅니다.

## 이 문서를 읽는 법

- 백틱 안의 글은 이름이나 값입니다. 글자 그대로 씁니다.
- 큰따옴표 안의 글은 화면에 나오는 글자이거나 코드에 들어가는 값입니다. 한 글자도 바꾸지 않습니다. 단, 프롬프트 마지막 참고 줄의 큰따옴표 안은 이 문서의 절 제목입니다.
- "쓰는 단계"는 그 내용을 만드는 프롬프트 번호입니다. 프롬프트 맨 앞의 `[2-14]` 같은 표시가 이번 단계입니다. 그 번호가 "쓰는 단계"나 줄 앞에 적힌 내용만 만들고, 다른 번호의 내용은 그 프롬프트를 받기 전에 만들지 않습니다.
- "만들지 않는 것" 절에 적힌 기능은 완료 브랜치 코드에 있어도 만들지 않습니다.
- 창고 쪽 이름은 공장 쪽 이름의 `factory`를 `warehouse`로 바꾼 같은 이름입니다.

## 이 회차에서 만드는 것

- 시작 상태: 서버를 켜면 오늘 운영 화면의 틀이 보이고 숫자는 화면 파일에 적어 둔 고정값입니다.
- 끝 상태: 수량, 달성률, 시간별 그래프, 상태 배지, 기록 처리 상태가 예시 자료에서 채워지고, 값이 없으면 0이 아니라 "확인 불가"로 보입니다. 다섯 화면 주소가 열리고 기록 화면에서 시간대를 골라 기록 표를 봅니다. 헤더의 알림 목록과 "?" 도움말 다섯 개가 열리고 닫힙니다.
- 이번에 건드리지 않는 곳: 이번 회차는 화면 파일만 만들거나 고칩니다. 화면 서버(`scripts/serve.mjs`)는 고치지 않으므로 서버를 다시 켤 필요가 없습니다.

`API_CONTRACT.md`는 강사가 준 API 설명서입니다. 이번 회차에는 2·3절(필드 이름과 값), 5절(예시 응답), 6절(예시 기록)을 씁니다.

## 앞 회차에서 바뀌는 것

없습니다. 1회차 약속은 그대로이고 1회차에 화면 파일에 적어 둔 고정 글자가 예시 자료 값으로 채워질 뿐입니다.

## 예시 자료와 화면 코드의 구성

쓰는 단계: 2-2, 2-7, 2-9

자료를 읽는 규칙과 통째로 새로 그려도 되는 곳은 2-2부터 모든 단계에 적용합니다. `render`를 부르는 약속은 2-7 뒤 모든 단계에 적용합니다. 2-2에서 예시 응답과 화면 JavaScript 파일을 만들고, 2-7에서 코드를 함수로 정리하며, 2-9에서 예시 기록을 더합니다. 예시 자료의 "지금"이 고정되어 있어 내 컴퓨터 시계와 상관없이 늘 같은 화면이 나옵니다.

### 약속

예시 자료와 화면 JavaScript는 각각 한 파일입니다.

| 파일 | 내용 |
|---|---|
| `public/sample-data.js` | 예시 자료입니다. `API_CONTRACT.md` 5절 예시 응답을 글자 그대로 `window.SAMPLE_SNAPSHOT = { … };` 로, 6절 예시 기록을 `window.SAMPLE_RECORDS = { production: […], shipment: […] };` 로 둡니다. 이 파일은 3회차에 지웁니다. |
| `public/app.js` | 화면 JavaScript는 이 한 파일입니다(모듈·프레임워크 없이). |

`index.html` head에서 `sample-data.js`, `app.js` 순서로 `defer`를 붙여 부릅니다.

자료를 읽는 규칙입니다.

- 자료의 필드 이름과 값은 `API_CONTRACT.md` 2·3절을 따릅니다.
- 화면의 "지금"은 자료의 `viewTime`이고 브라우저 시계는 쓰지 않습니다.

화면을 그리는 규칙입니다.

- 화면 그리기는 자료 하나로 화면 전체를 채우는 함수 하나(`render`)가 맡습니다.
- 마지막 자료를 기억해 두고 인자 없이 부르면 그 자료로 다시 그립니다.
- 공장과 창고는 같은 함수를 함께 씁니다.
- 버튼이나 주소 바뀜 처리에서는 직접 그리지 말고 `render`를 부릅니다.

안을 통째로 새로 그려도 되는 곳은 아래뿐입니다. 나머지는 `index.html`의 요소를 찾아 바꿉니다.

- 기록 처리 상태 카드 안
- 그래프 칸 안
- 기록 표 자리
- 조회 기록 화면
- 알림 목록 안

### 단계별로 만드는 것

| 단계 | 만드는 것 |
|---|---|
| 2-2 | `window.SAMPLE_SNAPSHOT`까지만 넣습니다. 예시 기록은 2-9에서 더합니다. |
| 2-7 | 화면을 하나도 바꾸지 않고, 달성률 글자·수량 글자·시각 글자·몇 분 전·늦은 기록 판단이 여러 곳에 흩어져 있으면 각각 함수 하나로 모읍니다. 한 현장의 생산·출고 카드, 그래프, 운영 상태 카드, 기록 처리 상태 카드를 채우는 함수 하나를 만들어 공장과 창고가 함께 쓰게 합니다. 자료 하나로 화면 전체를 채우는 그리기 함수를 만들어 페이지를 열 때 한 번 부릅니다. |
| 2-9 | 파일 끝에 `window.SAMPLE_RECORDS`를 더합니다. 이미 있는 예시 응답 부분은 바꾸지 않습니다. |

## 시각·수량·달성률 글자

쓰는 단계: 2-2 ~ 2-4

화면 여러 곳에서 함께 쓰는 글자 규칙입니다.

### 약속

시각 글자입니다.

- 시각 글자는 한국 시간 "2026. 10. 26. 09:00:00" 꼴입니다.
- 만드는 방법은 `Intl.DateTimeFormat("ko-KR")`, `timeZone "Asia/Seoul"`, `year numeric`, 나머지 `2-digit`, `hourCycle "h23"`입니다. `hour12`는 쓰지 않습니다.
- 그래프 아래는 "09시"입니다.
- 시각이 아니면 "기록 없음"입니다.

수량입니다.

- 수량은 0 이상의 안전한 정수(`Number.isSafeInteger`)만 수로 보고 `toLocaleString("ko-KR")`로 씁니다.
- 아니면 "확인 불가"이고 0으로 바꾸지 않습니다.
- 한 현장 값이 틀려도 다른 현장은 그대로 보입니다.

달성률입니다.

- 달성률은 실적 ÷ 목표 × 100을 소수 첫째 자리까지 씁니다.
- 실적·목표가 수가 아니거나 목표가 0이면 달성률 대신 안내를 쓰고 진행 막대와 "목표 초과"를 숨깁니다.
- 막대 값은 반올림하지 않고 100을 넘지 않습니다.

### 단계별로 만드는 것

시각을 "2026. 10. 26. 09:00:00" 꼴 한국 시간 글자로 바꾸는 기능과, 시만 "09시" 꼴로 쓰는 기능은 2-4에서 그래프와 함께 만듭니다.

## 시간별 그래프

쓰는 단계: 2-4, 2-15

2-4에서 막대와 그래프 주변 글자를, 2-15에서 키보드 이동을 만듭니다. 화면 읽기 프로그램은 눈이 불편한 사용자에게 화면 내용을 읽어 주는 프로그램입니다. 이 프로그램용 설명은 화면에는 보이지 않고 `svg`의 `aria-label`에 들어갑니다.

### 약속

그래프는 라이브러리 없이 SVG로 그립니다.

- 한 시간에 막대 하나입니다. 첫 시각부터 시간 차만큼 오른쪽으로 옮기고, 기록이 없는 시간은 빈자리로 둡니다.
- `quantity` 0은 높이 0 막대와 수량 "0"입니다.
- 막대는 막대마다 `rect` 하나이고 그래프 SVG에 다른 `rect`를 두지 않습니다.
- 막대 칸 간격은 `90px`이고, 그래프 칸에서 좌우 방향키는 한 번에 `90px` 움직입니다.
- 다시 그릴 때는 SVG만 바꾸고 가로 스크롤 위치를 지킵니다.

### 화면 글자

| 단계 | 자리 | 글자 |
|---|---|---|
| 2-4 | 막대 위 | 수량 |
| 2-4 | 막대 아래 | "09시" 꼴 시각 |
| 2-4 | 그래프 왼쪽 위 | 단위 "개" |

- 2-15: 그래프를 다시 그려도 옆으로 밀어 둔 위치가 처음으로 돌아가지 않게 합니다.

## 운영 상태 카드

쓰는 단계: 2-5

2-5에서 배지와 설명 글, 작은 글과 늦은 기록 판단을 만듭니다.

### 약속

상태 값마다 배지의 글자와 색이 정해져 있습니다.

| 상태 값 | 배지 글자 | 색 |
|---|---|---|
| `normal` | 정상 | `good` |
| `warning` | 확인 필요 | `warning` |
| `error` | 오류 | `danger` |
| `sent` | 전송 성공 | `good` |
| `failed` | 실패 | `danger` |
| `unknown` | 확인 불가 | `warning` |
| `waiting` | 대기 | `warning` |
| 목록에 없는 값 | "확인 필요" | `warning` |

늦은 기록은 마지막 발생 시각(`lastEventAt`)으로 판단합니다. 공장·창고 배지는 이 판단을 따릅니다.

| 마지막 발생 시각(`lastEventAt`) | 판단 | 공장·창고 배지 |
|---|---|---|
| 없거나 "지금"보다 늦으면 | `missing` | `waiting` |
| 30분 넘게 지났으면 | `stale` | `warning` |
| 그 밖 | `fresh` | 자료의 `status` |

"몇 분 전"은 내림한 분입니다.

현장 `status`가 `error`면 그 운영 상태 카드에, 알림 `status`가 `failed`면 알림 카드에 `danger` class를 더합니다.

### 화면 글자

| 단계 | 자리 | 글자 |
|---|---|---|
| 2-5 | 공장·창고 카드 설명 글 | 예시 자료에 있는 현장 설명("기록이 반영되고 있습니다.") |
| 2-5 | 알림 카드 설명 글, 전송 성공일 때 | "알림 전송이 완료됐습니다." |
| 2-5 | 알림 카드 설명 글, 실패일 때 | "담당자에게 알림을 전달하지 못했습니다." |
| 2-5 | 알림 카드 설명 글, 그 밖 | "전송 기록을 확인할 수 없습니다." |
| 2-5 | 공장·창고 카드 작은 글 | "기준 시각 대비: 15분 전 · 발생 시각: 2026. 10. 26. 12:55:00" 꼴 |
| 2-5 | 시각이 없거나 기준 시각보다 늦을 때 "15분 전" 자리 | "시각 확인 필요" |
| 2-5 | 알림 카드 작은 글 | "마지막 전송 시도: 2026. 10. 26. 12:30:00" 꼴 |

### 동작

- 2-5: 공장·창고 기록이 30분 넘게 들어오지 않았으면 운영 상태 배지를 "확인 필요"로, 마지막 기록 시각이 없으면 "대기"로 바꿉니다.

## 기록 처리 상태 카드

쓰는 단계: 2-6

기록이 발생하고 서버가 접수해 처리하기까지의 시각을 현장별로 보여 주는 카드입니다.

### 약속

서버 처리 시각이 없으면 "기록 대기", 단 `processingState`가 `paused`면 "처리 중단"입니다.

기록 표(2-9)의 상태 칸에 쓰는 기록 상태의 글자입니다.

| 기록 상태 | 글자 |
|---|---|
| `completed` | 완료 |
| `receipt-wait` | 접수 대기 |
| 그 밖 | 처리 대기 |

기록 처리 상태 카드(id `factory-flow`) 안의 시각 세 줄은 `dl` 하나에 `dt`(기록 발생, 서버 접수, 서버 처리)와 `dd`(시각 글자) 세 쌍으로 둡니다.

시각 세 줄의 꾸미기는 2-6에서 `styles.css`에 함께 넣습니다. 줄마다 `div` 하나로 `dt`와 `dd`를 묶습니다.

| 요소 | 모양 |
|---|---|
| `dl` | class `time-list`, 위 바깥 여백 24px |

화면 이벤트의 규칙입니다.

- 화면 이벤트(클릭, 키, 창 크기)는 페이지를 열 때 한 번만 붙이고 그릴 때마다 다시 붙이지 않습니다.
- Escape는 `document`의 `keydown` 하나에서 받아 열린 알림 목록과 도움말을 함께 닫습니다.
- 바깥을 눌러 닫는 처리와 부딪히지 않게 도움말 버튼의 클릭·키 처리에서 이벤트 전파를 막지 않습니다(`stopPropagation`을 쓰지 않음).

다시 그릴 때의 규칙입니다.

같은 화면을 다시 그릴 때는 표와 막대 줄의 가로 스크롤 위치와 초점을 지키고, 그릴 내용이 지난번과 같으면 표를 다시 만들지 않습니다. 주소가 바뀐 뒤 처음 그릴 때는 지키지 않습니다.

### 동작

- 2-10: "시간대 조회"를 누르는 처리는 페이지를 열 때 한 번만 붙입니다.
- 2-14: Escape는 알림 목록과 도움말을 함께 닫고, 알림 버튼에 초점을 돌려주는 것은 그대로 둡니다.
- 2-16: "본문으로 이동" 링크를 누르면 주소는 그대로 두고 본문으로 초점과 스크롤을 옮깁니다. "요청한 주소의 화면이 없어 오늘 운영으로 이동했습니다." 안내가 뜨면 안 됩니다.
- 2-17: 같은 화면을 다시 그릴 때 기록 표와 조회 기록 화면의 옆으로 민 위치와 초점이 그대로 남게 합니다. 주소가 바뀐 뒤 처음 그릴 때는 지키지 않습니다.
- 2-17: 기록 표에 그릴 내용이 지난번과 같으면 표를 다시 만들지 않습니다. 두 칸의 값과 고를 수 있는 범위는 이와 상관없이 늘 맞춥니다.

## 사용자가 직접 하는 일

AI 도구는 아래 일을 실행하지 않습니다.

- 브라우저로 화면 확인하기.
- 커밋(2-18).

화면 서버는 사용자가 켜 달라고 할 때 AI 도구가 1회차 문서 '화면 서버 켜기' 절대로 새 PowerShell 창에서 켭니다. 다 쓴 서버를 끄는 일(서버 창을 닫거나 Ctrl+C)은 사용자가 합니다. 이번 회차는 화면 파일만 고치므로 서버를 다시 켤 필요가 없습니다.
