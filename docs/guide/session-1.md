# 1회차 보충 문서: 화면 틀 만들기

> 이 문서는 1회차 프롬프트가 만드는 내용의 자세한 약속입니다. 1회차가 첫 문서입니다. 뒤 회차 문서가 다르게 적으면 뒤 문서를 따릅니다.

## 이 문서를 읽는 법

- 백틱 안의 글은 이름이나 값입니다. 글자 그대로 씁니다.
- 큰따옴표 안의 글은 화면에 나오는 글자이거나 코드에 들어가는 값입니다. 한 글자도 바꾸지 않습니다. 사용자가 글자를 바꿔 달라고 하면 바꿉니다. 단, 프롬프트 마지막 참고 줄의 큰따옴표 안은 이 문서의 절 제목입니다.
- "쓰는 단계"는 그 내용을 만드는 프롬프트 번호입니다. 프롬프트 맨 앞의 `[2-14]` 같은 표시가 이번 단계입니다. 그 번호가 "쓰는 단계"나 줄 앞에 적힌 내용을 만들고, 다른 번호의 내용은 그 프롬프트가 올 때 만듭니다. 사용자가 다른 번호의 내용도 함께 만들어 달라고 하면(밀린 단계를 따라잡을 때 등) 그대로 만듭니다.
- "만들지 않는 것" 절에 적힌 기능은 완료 브랜치 코드에 있어도 기본으로는 만들지 않습니다. 사용자가 만들어 달라고 하면 완료 브랜치 코드를 보고 만듭니다.
- 창고 쪽 이름은 공장 쪽 이름의 `factory`를 `warehouse`로 바꾼 같은 이름입니다.
- 이 문서의 "…하지 않습니다", "건드리지 않는 곳", "…없이", "…만", "기본으로" 같은 말은 모두 프롬프트를 따라갈 때의 기본입니다. 사용자가 다르게 부탁하면 AGENTS.md의 "사용자의 부탁이 먼저"대로 합니다.

## 이 회차에서 만드는 것

- 시작 상태: 1-1에서 git 저장소로 만든 빈 폴더에 1-2에서 수업 저장소 `milestone-0`의 강사가 준 파일(로고, 현장 사진 두 장, `API_CONTRACT.md`), `.gitignore`, `AGENTS.md`, 이 문서를 가져온 상태입니다. 화면 파일은 없습니다.
- 끝 상태: `npm.cmd start`로 화면 서버(http://127.0.0.1:4173)가 켜지고 오늘 운영 화면에 다섯 영역이 차례로 보입니다. PC에서는 생산·출고 카드가 두 열, 폭 375px에서는 한 열입니다. 숫자는 아직 고정값(생산 100개 · 목표 120개, 출고 75개 · 목표 100개)이고 버튼과 화면 이동은 2회차부터 붙입니다.
- 2회차부터 만드는 것: 1회차에는 JavaScript가 없습니다. 화면을 나누는 일과 선택 상자·버튼의 동작은 2회차부터 만듭니다. 사용자가 먼저 만들어 달라고 하면 만듭니다.
- 순서: 1-3부터 1-10까지는 화면 파일을 만들고 꾸미기를 넣지 않습니다. 1-11부터 1-14까지는 `public/styles.css` (꾸미기 파일)을 고치고, index.html (첫 화면 파일)은 기본으로는 더 고치지 않습니다. 사용자가 부탁하면 고칩니다.
- 이번 프롬프트 번호가 쓰는 단계에 있는 내용을 만듭니다. 그 내용은 화면에 보이지 않는 것까지 빠뜨리지 않습니다.

## 웹 서비스의 기본 약속

쓰는 단계: 1-3 ~ 1-14

이 절은 따로 만드는 것이 아니라 모든 단계에 적용되는 약속입니다. 꾸미기에 관한 내용은 꾸미기 단계에서 적용합니다.

### 약속

**어떤 웹 서비스인가.** 텀블공장(텀블러 공장)의 생산·출고를 보는 운영 대시보드입니다. 화면 글은 모두 한국어입니다.

**폴더 배치.**

| 무엇 | 어디에 | 언제부터 |
|---|---|---|
| 화면 파일 | `public` 폴더 | 1회차 |
| 화면 서버 | `scripts/serve.mjs` | 1회차 |
| 내 서버(NestJS) | `backend` 폴더 | 4회차부터 |
| Google Apps Script 코드 | `gas` 폴더 | 5회차부터 |

**화면 파일.** 화면은 `public/index.html` 한 페이지와 `public/styles.css` 한 파일입니다. 2회차부터 JavaScript는 `public/app.js` 한 파일입니다. 없는 주소용 화면은 `public/404.html`입니다.

**강사가 준 파일.** 기본으로 이름과 위치를 바꾸지 않습니다. 사용자가 부탁하면 바꿉니다.

| 파일 | 위치 |
|---|---|
| 로고 | `public/assets/tumble-factory-logo.png` |
| 현장 사진 | `public/assets/approved/factory.png`·`warehouse.png` |
| `API_CONTRACT.md` | 맨 위 |

**화면 주소.** URL 해시 (주소 끝의 # 부분)로 화면을 구분합니다. 1회차에는 링크만 두고 해시 라우팅 (주소 끝의 # 값에 따라 화면을 나누는 기능)은 2회차에 합니다.

| 주소 끝 | 화면 |
|---|---|
| `#/today` | 오늘 운영(기본) |
| `#/records/factory` | 오늘 생산 기록 |
| `#/records/warehouse` | 오늘 출고 기록 |
| `#/queries/factory` | 생산 데이터 조회 기록 |
| `#/queries/warehouse` | 출고 데이터 조회 기록 |

**오늘 운영 영역 순서.** 위에서부터 아래 차례입니다.

1. 먼저 확인할 일
2. 생산·출고 카드(공장·창고)
3. 운영 상태(공장·창고·알림 카드 세 장)
4. 기록 처리 상태(공장·창고)
5. 데이터 조회 기록(공장·창고)

**상태 색.** class 네 개로 나타냅니다. 배지, 알림 버튼, 조회 상태 점, 먼저 확인할 일 상자가 같은 이름을 씁니다. 노란 안내 상자는 class `"notice warning"`입니다.

| class | 색 |
|---|---|
| `good` | 초록 |
| `warning` | 노랑 |
| `danger` | 빨강 |
| `neutral` | 회색 |

**화면 폭.**

| 폭 | 모양 |
|---|---|
| PC(폭 701px 이상) | 생산·출고 카드 두 열 |
| 폭 700px 이하(휴대폰 확인은 375px) | 생산·출고 카드 한 열 |
| 375px | 페이지 가로 스크롤이 생기지 않습니다 |

**누르기와 숨기기.** 버튼, 카드 아래 링크, 입력 칸은 높이 44px 이상입니다. 키보드 초점은 초록 테두리로 보이게 합니다. 숨길 요소는 `hidden` 속성으로 숨기고 CSS에 `[hidden] { display: none !important; }`를 둡니다.

## 화면 서버

쓰는 단계: 1-3

화면 서버는 화면 파일을 보내는 작은 서버입니다. 자료는 3회차부터 이 화면 서버가 아니라 API 서버에서 받으므로, API 주소로 온 요청에는 파일을 찾지 않고 안내 문장으로 답합니다. 파일을 고친 뒤 새로고침하면 바로 보이도록 모든 응답에 저장하지 말라는 표시를 붙입니다.

### 약속

**서버를 여는 방법.** 화면 서버는 Node.js 기본 모듈(`node:http`, `node:fs`, `node:path`)만 씁니다. `127.0.0.1`에서만 엽니다. 포트는 환경 변수 `PORT`, 없으면 `4173`입니다. 켜지면 `"http://127.0.0.1:<실제 포트>"` 한 줄을 출력합니다.

**파일을 찾는 방법.** `public` 폴더는 명령을 실행한 폴더가 아니라 `serve.mjs`가 있는 폴더 기준(`../public`)으로 찾습니다. `serve.mjs`가 있는 폴더는 기본 모듈 셋만 쓰도록 `import.meta.dirname`으로 구합니다.

**주소를 읽는 방법.** 주소의 ? 뒤는 무시하고 경로를 `decodeURIComponent`로 푼 뒤 판단합니다. `/`는 `index.html`입니다.

모든 응답에 `Cache-Control: no-store`를 붙입니다. 아래 두 표의 응답이 모두 해당합니다.

**파일 종류.**

| 파일 | Content-Type |
|---|---|
| html | `text/html; charset=utf-8` |
| css | `text/css; charset=utf-8` |
| js | `text/javascript; charset=utf-8` |
| png | `image/png` |
| 그 밖 | `text/plain; charset=utf-8` |

**파일을 보내지 않는 경로.**

| 경로 | 상태 | Content-Type | 보내는 것 |
|---|---|---|---|
| `/api/`로 시작하는 경로 | `404` | `application/json; charset=utf-8` | 파일을 찾지 않고 아래 "값과 모양"의 글 |
| 없는 파일, 풀 수 없는 경로, `public` 밖을 가리키는 경로 | `404` | `text/html; charset=utf-8` | `404.html` 내용 |

### 값과 모양

`/api/`로 시작하는 경로의 응답 본문입니다.

```json
{"error":"이 서버는 화면 파일만 보냅니다. 화면은 public/config.js의 apiBaseUrl로 API 서버를 직접 부릅니다."}
```

## 화면 뼈대

쓰는 단계: 1-3

건너뛰기 링크, 머리 부분, 본문 자리, 바닥글을 만듭니다. 꾸미기와 JavaScript는 넣지 않습니다.

### 약속

- 첫 화면 맨 앞에 키보드 사용자용 건너뛰기 링크를 넣고 그 뒤에 머리 부분을 만듭니다.
- 머리 부분 안에는 나중에 버튼을 넣을 빈 오른쪽 묶음 하나를 둡니다.
- 머리 부분 왼쪽에 강사가 준 로고, 글자 두 개를 두고, 누르면 오늘 운영 주소(`#/today`)로 가게 합니다. 작은 글자는 큰 글자의 옆에 둡니다.
- 머리 부분 아래에 본문 자리를 만들고 그 안에 "오늘 운영" 제목을 둡니다. 제목 아래에는 설명과 비어 있는 오늘 운영 영역을 차례로 둡니다. "본문으로 이동"을 누르면 여기로 옵니다.
- 본문 맨 끝에 노란 안내를 넣습니다. 이 안내는 JavaScript가 꺼진 브라우저에서만 보입니다. 평소에는 보이지 않습니다. 그래도 꼭 만듭니다.
- 본문 아래에 바닥글을 둡니다.
- 이 문서의 '머리 부분'은 화면 맨 위 줄입니다. 프롬프트와 회차 문서에서는 '화면 맨 위'라고 부릅니다.
- 이 번호에서 만들지 않는 것: 머리 부분 오른쪽 묶음 안의 기준 시각·새로고침·알림(1-5), 카드(1-6 ~ 1-10), 꾸미기(1-11 ~ 1-14).

## 화면 서버 켜기

쓰는 단계: 1-4

화면 서버는 프롬프트나 사용자가 켜 달라고 할 때, 그리고 사용자가 부탁한 일(화면 확인 등)에 서버가 필요할 때 AI 도구가 켭니다. AI 도구의 터미널이 아니라 새 PowerShell 창을 열어 그 창에서 켭니다. AI 도구에 따라서는 30초가 지나면 그 터미널에서 켠 서버를 함께 끄기 때문입니다(아래 "오래 걸리는 명령"). 사용자가 AI 도구의 터미널에서 켜 달라고 하면 서버가 30초 뒤 꺼질 수 있다고 한 줄 알린 뒤 부탁대로 합니다. 이 새 창이 서버 창입니다. 서버가 AI 도구의 대화와 떨어진 창에서 돌고, 사용자는 이 창에서 서버가 출력한 줄과 빨간 오류 줄을 봅니다. 2회차부터 회차를 시작할 때 사용자가 "화면 서버를 켜 주세요."라고 보내면 같은 순서로 켭니다.

서버는 `node --watch`로 켭니다("프로젝트 파일"의 `package.json`). 서버 파일이 바뀌면 서버가 같은 창에서 알아서 다시 켜지므로, 다시 켜려고 서버를 끄거나 새 창을 열 필요가 없습니다. 사용자가 서버를 끄거나 새 창에서 켜 달라고 하면 그대로 합니다. 서버마다 창은 하나입니다. HTML·CSS·화면 JavaScript만 고쳤으면 브라우저만 새로고침합니다. 4회차의 내 서버(3000)도 같은 방식입니다.

### 약속

**켜기 전 확인.** 먼저 `package.json`의 `start`가 "프로젝트 파일"의 값(`node --watch scripts/serve.mjs`)인지 봅니다. 다르면 그 값으로 고칩니다. 사용자가 start를 바꿔 달라고 했으면 그대로 둡니다. 그다음 4173번 포트를 듣는 프로세스가 있는지 봅니다.

```powershell
Get-NetTCPConnection -LocalPort 4173 -State Listen -ErrorAction SilentlyContinue | Select-Object -ExpandProperty OwningProcess -Unique
```

- 프로세스 번호가 나오면 아래 명령으로 그 번호의 명령 줄을 봅니다. 명령 줄에 `scripts/serve.mjs`가 있으면 화면 서버가 이미 켜져 있는 것입니다. 새로 켜지 않고 "이미 켜져 있습니다"라고 알립니다. 이때 "감시 확인"에 아무것도 나오지 않으면 `--watch` 없이 켠 예전 방식 서버이니 "다시 켤 때"의 마지막 항목대로 합니다.
- 명령 줄에 `scripts/serve.mjs`가 없으면 다른 프로그램이 4173번 포트를 쓰고 있는 것입니다. 그 프로그램은 그대로 두고, 다른 프로그램이 4173번 포트를 쓰고 있다고 사용자에게 알립니다. 사용자가 그 프로그램을 꺼 달라고 하면 `Stop-Process -Id (프로세스 번호)`로 끄고, 포트가 빈 것을 확인한 뒤 "새 창에서 켜기"로 켭니다.
- 아무것도 나오지 않으면 "감시 확인"을 합니다. 줄이 나오면 서버 창이 열려 있고, 서버가 오류로 멈춘 채 파일이 바뀌기를 기다리는 중입니다. 이때는 새 창을 열 필요가 없습니다. "오류 줄 보기"로 직접 보고(사용자가 빨간 줄을 붙여 넣었으면 그 줄을 씁니다), 고친 뒤(고칠 것이 없으면 바로) "다시 켤 때"대로 같은 창에서 다시 켭니다. 감시 확인에도 아무것도 나오지 않으면 아래 "새 창에서 켜기"로 켭니다.

```powershell
Get-CimInstance Win32_Process -Filter "ProcessId=(프로세스 번호)" | Select-Object -ExpandProperty CommandLine
```

**감시 확인.** 서버 창에서 `--watch`로 도는 Node 프로세스가 있는지 봅니다. 포트를 듣는 것은 이 프로세스가 띄운 서버이고, 이 프로세스는 서버가 오류로 멈춰도 창과 함께 남아 있습니다.

```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" | Where-Object { $_.CommandLine -like '* --watch *scripts/serve.mjs*' } | Select-Object ProcessId, CommandLine
```

**새 창에서 켜기.** 아래 명령으로 새 PowerShell 창을 열고 그 창에서 화면 서버를 켭니다. 새 창은 경로를 다시 읽은 뒤 서버를 켜므로, AI 도구를 연 뒤 설치한 Node.js도 찾습니다. 이 명령에는 기다리기나 확인을 붙이지 않고, 확인은 다음 명령으로 따로 보냅니다. 웹 서비스 폴더가 `C:\ai-class\tumble-dashboard`가 아니면 그 경로로 바꿉니다. 서버가 꺼진 예전 서버 창이 남아 있으면 새 창을 열기 전에 "끄기"의 창 닫기 명령으로 닫은 뒤 엽니다(사용자가 닫아도 됩니다).

```powershell
Start-Process powershell -ArgumentList '-NoExit','-Command','$env:Path = [Environment]::GetEnvironmentVariable(''Path'',''Machine'') + '';'' + [Environment]::GetEnvironmentVariable(''Path'',''User''); cd C:\ai-class\tumble-dashboard; npm.cmd start'
```

- 몇 초 뒤 "켜기 전 확인"의 포트 명령으로 4173번 포트를 듣는 프로세스가 생겼는지 봅니다.
- 생겼으면 새 PowerShell 창에서 화면 서버를 켰으니 ego (lite) 브라우저에서 http://127.0.0.1:4173 을 열어 보라고 알립니다. 이때 서버 창이 보이지 않으면 알려 달라고 함께 적습니다(아래 "서버 창이 보이지 않을 때"). 사용자가 확인을 부탁하면 AI 도구가 ego (lite) 브라우저로 화면을 열어 확인합니다.
- 생기지 않았으면 "오류 줄 보기"로 직접 봅니다(사용자가 빨간 줄을 붙여 넣었으면 그 줄을 씁니다). 새 창을 또 열면 서버 창이 둘이 되어 고친 뒤 한쪽에 포트 오류가 나므로 기본으로는 열지 않습니다. 사용자가 새 창에서 켜 달라고 하면 "끄기"대로 남은 서버를 끈 뒤 엽니다. 사용자가 그 줄을 붙여 넣고 고쳐 달라고 하면 고친 뒤 "다시 켤 때"대로 같은 창에서 다시 켭니다.
- 서버 창의 오류 줄을 봐야 하면, 4173번 포트가 비어 있을 때 AI 도구의 터미널에서 아래 명령으로 서버를 몇 초만 켜 보고 나온 오류 줄을 봅니다. 서버가 켜지면 바로 끕니다. 이 문서에서 "오류 줄 보기"는 이 방법을 말합니다. 명령을 치기 직전에 포트를 한 번 더 보고, 그사이 서버가 켜졌으면 오류 줄 보기는 하지 않아도 됩니다. 오류 줄 보기가 끝난 뒤 포트가 비어 있으면, 감시 확인에 줄이 나올 때는 "다시 켤 때"대로 시작 파일의 수정 시각을 바꾸고, 줄이 없을 때는 "새 창에서 켜기"로 켭니다. 웹 서비스 폴더가 다르면 경로를 바꿉니다.

```powershell
$p = Start-Process node -ArgumentList 'scripts/serve.mjs' -WorkingDirectory 'C:\ai-class\tumble-dashboard' -NoNewWindow -PassThru; Start-Sleep 5; if (-not $p.HasExited) { Stop-Process -Id $p.Id }
```

**다시 켤 때.** 기본으로는 서버를 끄거나 새 창을 열지 않고 아래 순서로 같은 창에서 다시 켭니다. 사용자가 서버를 끄거나 새 창에서 켜 달라고 하면 그대로 합니다(끄는 방법은 아래 "끄기").

- `scripts/serve.mjs`를 고쳤으면 서버가 같은 창에서 알아서 다시 켜집니다. 서버 창에 `Restarting`으로 시작하는 줄과 서버 주소 줄이 다시 나옵니다.
- 파일을 고치지 않았거나 `serve.mjs` 밖의 파일을 고쳐서 다시 켜야 하면(사용자가 "화면 서버를 다시 켜 주세요."라고 할 때 등) 시작 파일의 수정 시각만 바꿉니다. 서버가 파일이 바뀐 것으로 보고 같은 창에서 다시 켜집니다. 웹 서비스 폴더가 다르면 경로를 바꿉니다.

```powershell
(Get-Item -LiteralPath 'C:\ai-class\tumble-dashboard\scripts\serve.mjs').LastWriteTime = Get-Date
```

- 다시 켜기 전에 4173번 포트를 듣는 프로세스 번호를 봐 둡니다. 다시 켠 뒤 몇 초 기다렸다가 그 번호가 바뀌었는지 봅니다. 바뀌었으면 다시 켜진 것입니다. 포트가 비어 있으면 "오류 줄 보기"로 직접 봅니다(사용자가 빨간 줄을 붙여 넣었으면 그 줄을 씁니다).
- 포트를 듣는 서버는 있는데 "감시 확인"에 아무것도 나오지 않으면 `--watch` 없이 켠 예전 방식 서버라 알아서 다시 켜지지 않습니다. 이때는 "켜기 전 확인"대로 `package.json`을 고치고, 4173번 포트를 듣는 프로세스를 "끄기"대로 끈 뒤 포트가 빈 것을 확인합니다. 예전 서버 창은 "새 창에서 켜기"대로 새 창을 열기 전에 닫고, 그다음 "새 창에서 켜기"로 켭니다.

**끄기.** 사용자가 서버를 꺼 달라고 하면 AI 도구가 끕니다. "감시 확인"에 나온 프로세스 번호와 "켜기 전 확인"의 포트 명령에 나온 프로세스 번호를 차례로 `Stop-Process -Id (프로세스 번호)`로 끄고, 두 명령에 아무것도 나오지 않는지 봅니다. 서버 창은 열린 채 남으니 닫아도 된다고 알립니다. 사용자가 서버 창을 닫아 달라고 하면 아래 명령으로 그 창과 그 안의 서버를 함께 끕니다(내 서버 창은 `-notlike '*\backend;*'`를 `-like '*\backend;*'`로 바꿉니다. 끝의 `$_.ProcessId -ne $PID`는 이 명령을 실행하는 PowerShell 자신을 빼는 조건이라 그대로 둡니다). 이 명령에 걸리는 창이 없으면(사용자가 직접 연 창 등) 위 방법으로 서버만 끄고, 남은 창은 닫아도 된다고 알립니다.

```powershell
Get-CimInstance Win32_Process -Filter "Name='powershell.exe'" | Where-Object { $_.CommandLine -like '*npm.cmd start*' -and $_.CommandLine -notlike '*\backend;*' -and $_.ProcessId -ne $PID } | ForEach-Object { taskkill.exe /PID $_.ProcessId /T /F }
```

 사용자가 직접 끌 때는 서버 창을 닫거나 그 창에서 Ctrl+C를 누릅니다. "일괄 작업을 끝내시겠습니까 (Y/N)?"가 나오면 `Y`를 칩니다.

**서버 창이 보이지 않을 때.** 사용자가 서버 창(4회차부터는 "화면 창")이 보이지 않는다고 하면 같은 명령으로 다시 열지 않습니다. "끄기"의 창 닫기 명령으로 그 창을 닫고, "켜기 전 확인"의 포트 명령과 "감시 확인"에 남은 것이 있으면 "끄기"대로 끕니다. 그다음 아래 명령을 글자 그대로 실행해 웹 서비스 폴더에 `start-server.bat`을 만들고 사용자가 열게 합니다(여는 법은 아래 "오래 걸리는 명령"의 "새 창이 보이지 않을 때"). 웹 서비스 폴더가 `C:\ai-class\tumble-dashboard`가 아니면 명령 맨 앞의 경로만 바꿉니다. 이 파일로 연 창도 경로를 다시 읽고, 명령 줄에 `npm.cmd start`가 든 powershell.exe라서 "끄기"의 창 닫기 명령으로 닫을 수 있습니다. `npm.cmd`를 전체 경로로 바꾸면 명령 줄이 달라져 닫지 못하므로 명령은 고치지 않습니다. 사용자가 열었다고 하면 "켜기 전 확인"의 포트 명령으로 4173번 포트가 열렸는지 봅니다.

```powershell
[IO.File]::WriteAllLines('C:\ai-class\tumble-dashboard\start-server.bat', [string[]]@('@echo off', 'cd /d "%~dp0"', 'powershell -NoExit -Command "$env:Path = [Environment]::GetEnvironmentVariable(''Path'',''Machine'') + '';'' + [Environment]::GetEnvironmentVariable(''Path'',''User''); npm.cmd start"'))
```


## 오래 걸리는 명령

AI 도구에 따라서는 AI가 실행하는 명령에 아래 제한이 있습니다. 이 절의 방법은 어느 AI 도구에서나 그대로 씁니다. 사용자가 다르게 실행해 달라고 하면 그 방식에서 생길 수 있는 일을 한 줄 알린 뒤 부탁대로 합니다.

- 명령 하나가 30초를 넘으면 그 명령과 그 명령이 띄운 프로그램을 함께 강제로 끝냅니다. 그때까지 나온 글은 AI에게 가지 않고 시간 초과 오류만 갑니다.
- 명령마다 새 PowerShell이 뜹니다. 앞 명령의 `cd`, `$env:Path`, 변수는 다음 명령에 남지 않습니다. 한 번에 여러 명령을 보내면 동시에 실행됩니다.
- 명령에는 입력을 넣을 수 없습니다. y/n이나 값을 묻는 질문에 답하지 못합니다.
- 프로그램 경로는 AI 도구가 명령을 실행하는 프로그램이 처음 켜질 때 정해지고, AI 도구를 닫았다 다시 열어도 그대로일 수 있습니다. 그 뒤에 설치한 프로그램은 경로를 다시 읽어야 찾을 수 있습니다.
- AI에게는 명령 결과 하나마다 앞뒤를 합쳐 8,000자쯤(앞 4,000자, 뒤 4,000자쯤)만 가고 가운데는 빠집니다.
- `Start-Process`로 새 창을 띄우고 바로 끝나는 명령은 30초 제한에 걸리지 않고, 새 창은 그대로 남습니다. 같은 명령 안에서 새 창을 기다리면 30초에 새 창까지 함께 꺼집니다. 서버를 켜는 명령(이 문서의 서버 켜기 절)이 새 창을 띄우고 바로 끝나는 것도 이 때문입니다.
- 실행 중인 명령을 떼어 계속 돌리는 단추가 AI 도구에 있어도 사용자에게 누르라고 하지 않고, 이 절의 새 창 방식으로 합니다.

### 한 명령에 담기

- 명령은 한 번에 하나씩 보냅니다. 순서가 있는 명령은 한 명령 안에 `;`로 잇습니다. `&&`로 이으면 PowerShell 판에 따라 문법 오류가 나기 때문입니다. 이어 쓴 명령이 합쳐서 30초를 넘길 수 있으면 하나씩 따로 보내거나 아래 "새 창에서 실행하기"로 합니다.
- `;`로 이은 뒤 명령은 앞 명령이 실패해도 실행됩니다. 앞 명령이 성공해야 하는 명령(올리기 뒤 배포 등)은 잇지 않고 따로 보내, 결과를 본 뒤 다음을 보냅니다.
- 다른 폴더에서 할 명령은 그 명령 앞에 `cd '(폴더 전체 경로)';`를 둡니다. 따로 보낸 `cd`는 다음 명령에 남지 않습니다.
- 경로 다시 읽기: `ego-browser`를 부르는 명령과 이 대화에서 설치한 프로그램을 부르는 명령에는 늘 맨 앞에 아래 줄을 붙이고 `<명령>` 자리에 부를 명령을 넣습니다. 그 밖의 명령도 찾지 못하면 이 줄을 붙여 다시 실행합니다. 이 줄만 따로 실행하면 다음 명령에 남지 않습니다. 그래도 찾지 못하면 그 프로그램 실행 파일의 전체 경로로 부릅니다.

```powershell
$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User'); <명령>
```

- 외부 프로그램에 넘기는 글: `curl.exe`, `git`, `ego-browser` 같은 외부 프로그램에 큰따옴표가 든 글(JSON 본문 등)을 넘기거나 파이프(`|`)로 한글을 넘길 때는 그 글을 파일로 저장해 파일로 넘깁니다. 인자 안의 큰따옴표는 PowerShell 판에 따라 사라지고, 외부 프로그램에 파이프로 넘긴 한글은 판에 따라 `?`로 바뀌기 때문입니다. 큰따옴표가 든 글과 브라우저 스크립트는 AI 도구의 파일 쓰기로 파일에 저장합니다. 예: `curl.exe`의 본문은 `--data-binary '@(파일 전체 경로)'`, 브라우저 스크립트는 아래 "ego (lite) 브라우저"의 꼴. `npm.cmd`처럼 `.cmd`로 설치된 명령도 같습니다. 따옴표로 감싼 인자 속 한글(예: `git commit -m '고친 내용'`)은 큰따옴표로 감쌌든 작은따옴표로 감쌌든 파일로 넘기지 않아도 됩니다.
- 묻는 명령: 묻지 않게 하는 옵션을 붙입니다. 예: `npx --yes`, `Remove-Item -Force`, `winget install (이름) --accept-source-agreements --accept-package-agreements`.
- `2>&1`: `git`, `npm.cmd` 같은 프로그램의 출력에 `2>&1`이나 `2>(파일)`을 붙이면 경고 한 줄에도 명령이 멈출 수 있습니다. 붙여야 하면 같은 명령 맨 앞에 `$ErrorActionPreference='Continue';`를 둡니다.
- 출력 줄이기: 출력이 길 것 같으면 `| Select-Object -Last 40`이나 `| Select-String '(찾을 글)'`을 붙여 필요한 줄만 봅니다. 파일 전체를 봐야 하면 아래 "긴 출력 읽기"대로 합니다.
- 문서와 코드 파일 읽기: AI 도구의 파일 읽기로 읽습니다. 명령으로 읽어야 하면 아래 "긴 출력 읽기"의 7,000자씩 읽는 명령에서 `"$env:TEMP\ai-out.txt"`만 `'(파일 전체 경로)'`로 바꿔 읽습니다. 그 명령은 `Get-Content -Raw -Encoding UTF8`로 읽고 7,000자씩 나눠 보여 줍니다. Windows PowerShell 5.1은 `-Encoding UTF8` 없이 읽으면 UTF-8 문서의 한글이 깨질 수 있고, 한 번에 보면 8,000자를 넘는 가운데가 빠져서, 어느 쪽이든 틀린 답이 나올 수 있기 때문입니다.

### 새 창에서 실행하기

아래 명령은 새 창에서 실행합니다. 빌드나 확인처럼 몇 초면 끝나는 명령만 AI가 명령을 실행하는 터미널에서 합니다. 서버를 켜는 일은 이 절이 아니라 이 문서의 서버 켜기 절을 따릅니다.

- 설치: 프로그램 설치, `npm.cmd install`, `npx`로 패키지를 처음 내려받는 명령. 설치는 늘 새 창에서 합니다. 설치가 끝났는지는 아래 "끝났는지 보기"대로 출력 파일의 마지막 줄 `AI-CMD-END:0`과 그 위 설치 결과를 함께 읽고 판단합니다.
- 30초를 넘길 수 있는 그 밖의 명령: 큰 저장소의 clone이나 첫 fetch, 회차 문서가 새 창에서 하라고 한 명령
- 로그인이 끝날 때까지 기다리는 명령: `gas:login` 같은 로그인 명령, `git push`(처음 올릴 때 Git 로그인 창이 뜨고 기다립니다)
- AI가 명령을 실행하는 터미널에서 30초에 끊긴 적이 있는 명령

`<명령>` 자리에 그 명령을 넣어(꺾쇠도 지웁니다) 실행합니다.

```powershell
Remove-Item $env:TEMP\ai-cmd.log -ErrorAction SilentlyContinue; (Start-Process powershell -PassThru -WorkingDirectory (Get-Location).Path -ArgumentList '-Command','$env:Path = [Environment]::GetEnvironmentVariable(''Path'',''Machine'') + '';'' + [Environment]::GetEnvironmentVariable(''Path'',''User''); [Console]::OutputEncoding = [Text.Encoding]::UTF8; & { <명령> 2>&1; ''AI-CMD-END:'' + $LASTEXITCODE } | ForEach-Object ToString | Tee-Object -FilePath $env:TEMP\ai-cmd.log').Id
```

- 이 명령은 이전 출력 파일을 지우고 새 창을 연 뒤 그 창의 프로세스 번호만 보여 주고 바로 끝납니다. 그래서 이 명령에는 기다리기나 확인을 붙이지 않습니다. 보여 준 번호는 끝났는지 볼 때 씁니다.
- 새 창은 경로를 다시 읽은 뒤 명령을 실행하므로, AI 도구를 연 뒤 설치한 프로그램도 찾습니다.
- `<명령>`에 든 따옴표는 큰따옴표든 작은따옴표든 모두 작은따옴표 두 개(`''`)로 바꿔 씁니다. 큰따옴표를 그대로 두면 새 창에 닿기 전에 사라집니다. 예: uv 설치는 `powershell -ExecutionPolicy ByPass -c ''irm https://astral.sh/uv/install.ps1 | iex''`입니다.
- `<명령>`에 `$env:…`를 넣지 말고, 그 값을 먼저 실행해 얻은 뒤 풀어 적습니다.
- 새 창은 이 명령을 실행한 폴더에서 시작합니다. 다른 폴더에서 실행해야 하면 `(Get-Location).Path`를 `'(폴더 전체 경로)'`로 바꿉니다.
- 환경 변수가 필요하면 같은 줄의 `Start-Process` 앞에 `$env:이름='값';`으로 둡니다.
- 새 창은 명령이 끝나면 저절로 닫힙니다. 출력은 `$env:TEMP\ai-cmd.log`에 남고, 마지막 줄에 `AI-CMD-END:(종료 코드)` 줄이 찍힙니다.
- 새 창에서 실행하는 명령은 한 번에 하나만 띄웁니다. 같은 출력 파일을 쓰므로, 앞 명령의 `AI-CMD-END` 줄을 본 뒤 다음 명령을 띄웁니다.

### 끝났는지 보기

아래 명령으로 15초 기다린 뒤 출력 파일의 끝 30줄을 봅니다. 한 번에 20초를 넘지 않으므로 `AI-CMD-END` 줄이 나올 때까지 이 명령을 되풀이하되, 사이에 아래 프로세스 번호 확인을 따로 보냅니다. 같은 명령을 바로 이어 보내면 AI 도구에 따라 멈추고 사용자에게 묻기 때문입니다(아래 "기다리기").

```powershell
Start-Sleep -Seconds 15; if (Test-Path $env:TEMP\ai-cmd.log) { Get-Content $env:TEMP\ai-cmd.log -Tail 30 } else { '아직 출력 파일이 없습니다' }
```

- `ai-cmd.log`는 AI 도구의 파일 읽기로 열지 않고 위 명령의 `Get-Content`로만 봅니다. 더 보려면 `-Tail` 숫자를 늘립니다.
- 마지막 줄이 `AI-CMD-END:0`이면 명령이 끝난 것입니다. 성공했는지는 그 위 글을 그 명령의 성공 기준과 맞춰 봅니다. 회차 문서에 성공 기준이 있으면 그 기준을 씁니다.
- `AI-CMD-END:` 뒤가 0이 아닌 숫자면 실패입니다. 그 위 글로 원인을 봅니다.
- `AI-CMD-END:` 뒤가 비어 있으면 종료 코드를 남기지 않는 PowerShell 명령입니다. 그 위 글로 성공했는지 봅니다.
- `AI-CMD-END` 줄이 없으면 새 창을 열 때 나온 번호로 아래 명령을 실행합니다. "실행 중"이면(출력 파일이 아직 없어도 첫 출력 전입니다) 새 창을 다시 띄우지 않고 위 확인을 되풀이합니다. "창이 닫혔습니다"면 창이 중간에 닫힌 것입니다. 그 위 글을 보고, 아래 "시간 초과로 끊겼을 때"처럼 결과가 이미 생겼는지 먼저 본 뒤 필요할 때만 다시 실행합니다.

```powershell
if (Get-Process -Id (번호) -ErrorAction SilentlyContinue) { '실행 중' } else { '창이 닫혔습니다' }
```

- 로그인을 기다리는 명령이 아닌데 10번(약 3분) 확인해도 로그 끝이 그대로면, 새 창이 무엇을 묻고 멈췄을 수 있습니다. 새 창에 보이는 글을 알려 달라고 하고 답을 끝냅니다.
- 로그인을 기다리는 명령은 아래 "사용자에게 넘기는 일"대로 합니다.

### 기다리기

- 문서나 따라하기에 "1분 기다린다"처럼 긴 기다림이 있으면 `Start-Sleep -Seconds 20` 이하로 나눠 여러 번 실행합니다. 기다린 뒤 확인까지 한 명령에 담으면 합쳐서 20초 이하로 합니다. 예: `Start-Sleep -Seconds 15; (확인 명령)`.
- 같은 명령을 바로 이어 다시 보내면 AI 도구에 따라 멈추고 사용자에게 물을 수 있습니다(같은 20초 대기를 다섯 번 이어 보냈을 때 다섯 번째에서 멈춘 기록이 있습니다). 기다리기와 확인을 한 명령에 담았어도 글자가 같으면 같은 명령입니다. 그래서 같은 명령을 바로 이어 보내지 않고, 사이에 기다리는 일의 상태를 확인하는 다른 명령을 따로 보냅니다. 상태 확인에서 아직 처리 중일 때만 다음 대기를 합니다.
- 사용자가 몇 분 뒤에 확인해 달라고 했으면 먼저 `Get-Date -Format 'HH:mm:ss'`로 시각을 봐 두고 그 시각을 기준으로 삼습니다. 중간에 AI 도구가 멈추고 사용자에게 물었다가 다시 이어 가도 시간을 처음부터 다시 세지 않습니다. 멈춰 있던 동안에도 시간은 지났기 때문입니다.
- 무엇이 생길 때까지 기다릴 때는 확인 명령을 여러 번 보냅니다. 되풀이하는 고리(`while` 등)를 한 명령에 넣으면 그 명령이 30초를 넘길 수 있기 때문입니다.

### 시간 초과로 끊겼을 때

- 30초에 끊긴 명령은 시간 초과 오류만 남고 출력은 오지 않습니다. 실패가 아니라 어디까지 됐는지 모르는 상태입니다.
- 다시 실행하기 전에 그 명령의 결과가 이미 생겼는지 먼저 봅니다. 예: 만들어진 파일이나 폴더, 설치된 명령의 버전, Apps Script 배포 목록, 시트의 끝 줄.
- 결과가 생겼으면 다시 실행하지 않습니다. 생기지 않았으면 "새 창에서 실행하기"로 다시 실행합니다. 설치가 중간에 끊겼으면 새 창에서 같은 설치를 다시 실행합니다.
- ego (lite) 브라우저에서 단추를 누르는 실행이 끊겼을 때도 같습니다. 같은 단추를 다시 누르기 전에 결과가 생겼는지 먼저 봅니다.

### 긴 출력 읽기

- 출력이 8,000자를 넘을 것 같으면(긴 파일을 `git --no-pager show`로 읽을 때 등) 파일로 저장합니다. 마지막 부분은 저장한 파일의 전체 경로를 보여 줍니다.

```powershell
[Console]::OutputEncoding = [Text.Encoding]::UTF8; <명령> | Out-File -Encoding utf8 -FilePath "$env:TEMP\ai-out.txt"; "$env:TEMP\ai-out.txt"
```

- 저장한 파일은 AI 도구의 파일 읽기로, 위 명령이 보여 준 전체 경로를 열어 읽습니다. 한 번에 다 나오지 않으면 나눠 읽습니다.
- 파일 읽기로 열지 못하면 아래 명령으로 7,000자씩 읽습니다. 처음에는 `$s = 0`이고, 다음 조각은 `7000`, `14000`처럼 7,000씩 늘립니다.

```powershell
[Console]::OutputEncoding = [Text.Encoding]::UTF8; $s = 0; $t = Get-Content -Raw -Encoding UTF8 "$env:TEMP\ai-out.txt"; $t.Substring($s, [Math]::Min(7000, $t.Length - $s))
```

### ego (lite) 브라우저

- 이 대화에서 ego (lite) 브라우저를 처음 쓸 때 아래 명령으로 사용법 안내를 파일로 저장하고, "긴 출력 읽기"대로 첫 줄부터 `[ego-browser:skill] end of guide`로 시작하는 끝 줄까지 읽습니다. 안내를 명령 출력으로 바로 보면 가운데가 빠져도 끝 줄은 남아서 다 읽은 것처럼 보이므로, 꼭 파일로 읽습니다. 이 대화에서 이미 읽었으면 다시 읽지 않습니다.

```powershell
$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User'); [Console]::OutputEncoding = [Text.Encoding]::UTF8; ego-browser skill | Out-File -Encoding utf8 -FilePath "$env:TEMP\ego-browser-skill.md"; "$env:TEMP\ego-browser-skill.md"
```

- 스크립트는 파일로 넘깁니다. `-e`로 인자에 넣거나 파이프(`|`)로 넘기면 따옴표와 한글이 바뀔 수 있기 때문입니다. 먼저 `$env:TEMP`를 실행해 임시 폴더의 전체 경로를 보고, AI 도구의 파일 쓰기로 `(그 전체 경로)\ego-script.js`에 UTF-8로 저장합니다. 파일 쓰기에는 `$env:TEMP`나 `%TEMP%` 대신 그 전체 경로를 씁니다. 글자 그대로 쓰면 그 글자 이름의 폴더가 작업 폴더 안에 생기기 때문입니다.
- 첫 실행은 아래처럼 TaskSpace(작업 공간)를 만들고 그 번호를 찍습니다. 다음 실행부터는 `taskSpace("(작업 이름)")` 대신 찍힌 번호로 `await taskSpace((번호))`를 씁니다. 다음 답에서 같은 일을 이어 갈 때는 사용법 안내의 "Starting and ending a reply"대로 그 번호로 잇습니다.

```javascript
const task = await taskSpace("(작업 이름)");
const page = task.page("p1");
await page.goto("(주소)", { timeout: 15000 });
console.log({ taskSpaceId: task.spaceId });
console.log(String(await page.snapshot()).slice(0, 7000));
```

- 그다음 아래 명령으로 실행합니다. 실행이 끝나면 스크립트 파일을 지우고 ego (lite) 브라우저의 종료 코드를 찍습니다. 스크립트를 바꿀 때마다 파일을 다시 저장하고 이 명령을 다시 실행합니다.

```powershell
$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User'); [Console]::OutputEncoding = [Text.Encoding]::UTF8; cmd /c "ego-browser nodejs < %TEMP%\ego-script.js"; $c = $LASTEXITCODE; Remove-Item $env:TEMP\ego-script.js; "ego-browser 종료 코드: $c"
```

- 한 번 실행은 20초 안에 끝나게 합니다. 한 실행에는 동작 하나와 짧은 확인만 담고, 한 실행 안의 `timeout`을 모두 더해 15초(15000) 이하로 줍니다.
- 찍는 글도 8,000자를 넘으면 가운데가 빠집니다. 위 예처럼 `.slice(0, 7000)`으로 자르고, 더 봐야 하면 `.slice(7000, 14000)`처럼 다음 실행에서 이어서 찍습니다.
- 몇 분 걸리는 일(처리 결과 기다리기, 학습 등)은 단추를 누르는 실행과 결과를 보는 실행을 나누고, 결과 보기를 20초 이하로 여러 번 합니다.
- 사람이 브라우저에서 해야 하는 순간이 오면 `await task.handOff()` 뒤 그 실행을 끝내고, 무엇을 하면 되는지 한 줄로 알린 뒤 답을 끝냅니다. `waitForControl()`로 같은 실행 안에서 기다리지 않습니다. 사용자가 마쳤다고 하면 `const task = await takeOverTaskSpace((번호));`로 같은 작업 공간을 이어받고, `task.userPage()`로 사용자가 보던 페이지를 씁니다.

### 사용자에게 넘기는 일

- 사람이 해야 하는 순간의 예: 사용자가 알려 주지 않은 비밀번호와 본인 확인 같은 로그인 단계, 사용자 계정 컨트롤(설치 승인 창), Git 로그인 창이나 로그인 명령이 연 Chrome 창처럼 AI가 누를 수 없는 창.
- 로그인 명령의 출력("끝났는지 보기" 명령으로 본 글)에 로그인 주소가 나오면 그 주소를 ego (lite) 브라우저에서 열어 AI가 할 수 있는 데까지 합니다. 사용자가 알려 주지 않은 비밀번호, 본인 확인, AI가 누를 수 없는 창에서만 할 일을 알리고 답을 끝냅니다.
- 그 순간을 만드는 명령은 "새 창에서 실행하기"로 띄우고, 브라우저 안의 일은 `task.handOff()`로 넘깁니다. 그다음 무엇을 하면 되는지 한 줄로 알리고 답을 끝냅니다. 한 명령 안에서 사람이 마치기를 기다리지 않습니다.
- 사용자가 마쳤다고 하면 "끝났는지 보기"나 그 일의 확인 명령으로 보고 이어서 합니다.
- 프로그램 설치를 새 창으로 띄울 때는 확인을 시작하기 전에 "사용자 계정 컨트롤(설치 승인 창)이 뜨면 '예'를 눌러 주세요"라고 먼저 알립니다. AI 도구에 따라 AI가 그 창이 뜬 순간을 알 수 없기 때문입니다.

### 새 창이 보이지 않을 때

- AI 도구나 PC에 따라 AI가 띄운 새 창(로그인 명령이 여는 Chrome 창, 서버 창 등)이 사용자 화면에 나타나지 않을 수 있습니다. 원인은 확인하지 못했습니다. 그래서 로그인 명령이 여는 Chrome 창이나 서버 창처럼 사용자가 보거나 눌러야 하는 새 창을 띄웠으면, 사용자에게 알리는 글에 "창이 보이지 않으면 알려 주세요"를 함께 적습니다.
- 출력에 나온 주소를 ego (lite) 브라우저에서 열어 진행하는 명령(로그인 주소를 내는 `gas:login` 등)에는 이 절의 방법을 쓰지 않습니다. 그 명령의 새 창과 그 명령이 연 브라우저는 사용자가 보지 않아도 되고, `.bat`으로 다시 띄우면 출력이 `ai-cmd.log`에 남지 않아 주소를 읽을 수 없기 때문입니다. 사용자가 창이나 브라우저가 보이지 않는다고 하면 그 주소를 ego (lite) 브라우저에서 엽니다. 이미 열었으면 다시 열지 않고 그 작업 공간을 이어 씁니다.
- 창이 보이지 않는다고 하면 같은 명령을 다시 띄우지 않습니다. 다시 띄워도 창이 보이지 않은 사례가 있기 때문입니다. 먼저 새 창을 열 때 나온 번호로 "끝났는지 보기"의 프로세스 확인을 해서 "실행 중"이면 `taskkill /PID (번호) /T /F`로 그 창과 그 창이 띄운 프로그램을 함께 끕니다. 남은 창이 같은 일을 하고 있으면 새로 여는 창과 겹칠 수 있기 때문이고, 프로그램 이름으로 한꺼번에 끄면 사용자가 쓰던 창까지 꺼지므로 번호로만 끕니다. 그다음 작업 폴더에 그 명령을 실행하는 `.bat` 파일을 만들어 사용자가 파일 탐색기(폴더와 파일을 보는 Windows 프로그램)에서 그 파일을 열게 합니다. 이 방법으로 창이 보인 사례가 있습니다. 서버 창은 새 창을 열 때 나온 번호가 없으니, 끄는 방법과 `.bat`의 꼴은 그 서버를 켜는 절을 따릅니다.
- `.bat` 파일은 `[IO.File]::WriteAllLines('(작업 폴더 전체 경로)\(이름).bat', [string[]]@('@echo off', '(첫 줄)', '(둘째 줄)'))`처럼 PowerShell 명령 하나로 만듭니다. 이렇게 만들면 BOM 없이 줄바꿈 CRLF로 저장됩니다. BOM이 붙고 줄바꿈이 CRLF가 아닌 `.bat`이 실행되지 않은 사례가 있는데, AI 도구의 파일 쓰기로는 이 둘을 AI가 고를 수 없기 때문입니다. 파일 안에는 영문과 경로만 씁니다. 한글은 그 PC의 기본 글자 방식으로 읽혀 깨질 수 있기 때문입니다. 실행할 프로그램은 전체 경로로 쓰되, 사용자 폴더 아래 경로는 `%USERPROFILE%`나 `%LOCALAPPDATA%`로 시작하고 작업 폴더는 `%~dp0`(그 `.bat`이 있는 폴더)로 적습니다. 그러면 계정 이름이나 폴더 이름에 한글이 있어도 파일 안에 들어가지 않습니다. 명령 앞에 두던 `$env:이름='값';`은 `set 이름=값` 줄로 넣습니다.
- 사용자가 파일을 열었다고 하면 그 일의 확인 명령(로그인 확인 명령, 포트 확인, 설치된 명령의 버전 등)으로 결과를 보고 이어서 합니다. `.bat`으로 연 창의 출력은 `ai-cmd.log`에 남지 않으므로 "끝났는지 보기"로 보지 않습니다.

## 화면 전체 기본 모양

쓰는 단계: 1-11

이 절부터는 `public/styles.css` (꾸미기 파일)을 고칩니다. index.html (첫 화면 파일)은 기본으로는 더 고치지 않습니다.

### 약속

- 모든 요소는 `box-sizing: border-box`로 둡니다.
- 흰 바탕에 짙은 회색 글자, 컴퓨터 기본 글꼴 16px이고 화면 가장자리 여백은 없앱니다.
- 제목과 문단의 기본 바깥 여백을 없애고 큰 제목·중간 제목·작은 제목 순서로 크기를 줄입니다. 본문 글자와 버튼 글자는 16px입니다.
- 링크와 입력 칸은 주변 글자 모양을 따릅니다. 키보드로 이동할 때는 초록 테두리가 보이게 합니다.
- 숨긴 요소는 확실히 안 보이게 합니다(웹 서비스의 기본 약속의 `[hidden]` 규칙).
- 글자를 끌어 선택하면 바탕이 연한 초록이 됩니다.
- 이 번호에서 만들지 않는 것: 머리 부분 모양(1-12), 두 열 배치(1-13), 휴대폰 폭 모양(1-14).

## 카드와 버튼 링크 모양

쓰는 단계: 1-11

카드 안쪽 모양, 버튼 모양 링크, 안내 상자를 꾸밉니다.

### 약속

- 카드는 연한 회색 테두리의 둥근 흰 상자로, 상자 안 글자가 테두리에 붙지 않게 안쪽 여백을 둡니다.
- 먼저 확인할 일 상자는 기본이 연한 빨강 둥근 상자이고, 회색 상태일 때는 회색 상자입니다.
- 카드의 수량 "생산 100개"는 크고 굵게, "· 목표 120개"는 그 옆에 작은 회색 글자로 한 줄에 둡니다. 숫자는 자리마다 폭이 같은 숫자 모양으로 씁니다.
- 카드 설명과 작은 시각 글은 회색으로, 배지는 작은 둥근 꼬리표로 꾸밉니다.
- 배지는 상태 색 네 가지(초록·노랑·빨강·회색)로 칠하고 빨강 상태 카드는 연한 빨강 바탕으로 보이게 합니다. 지금 화면에는 초록 배지만 보이지만 네 가지를 모두 넣습니다.
- 카드 아래 링크는 누르기 쉬운 높이로 하고 "생산 기록 보기"·"출고 기록 보기"는 검은 버튼처럼 꾸며 마우스를 올리면 조금 옅어지게 합니다.
- 안내 상자는 회색 테두리의 둥근 상자, 노란 안내 상자는 노란 바탕입니다.

## 머리 부분 모양

쓰는 단계: 1-12

화면 위쪽 머리 부분과 그 안의 버튼을 꾸밉니다.

### 약속

- 머리·본문·바닥글은 같은 최대 폭으로 가운데에 둡니다.
- 왼쪽 로고는 작게 줄이고 "텀블공장"과 작은 회색 "관제 대시보드"를 로고 옆 한 줄에 둡니다.
- 머리 부분 오른쪽 묶음은 오른쪽 끝에 한 줄로 두고 기준 시각 선택 상자는 누르기 쉬운 크기로 합니다.
- "확인 중" 앞에는 상태 색을 따르는 작은 동그라미 점을 붙입니다.
- 새로고침 버튼은 아이콘이 가운데 있는 테두리 정사각형으로, 옆의 "조회 중…"은 작은 회색 글자로 합니다.
- 누를 수 없는 상태의 새로고침 버튼은 흐리게 보이고 모든 버튼은 누르는 동안 살짝 작아집니다.
- 알림 버튼은 종 아이콘과 글자가 나란한 테두리 버튼으로 하고 빨강·노랑·회색 상태 색을 따르게 합니다.
- 마우스가 있는 PC에서는 새로고침 버튼과 알림 버튼에 마우스를 올리면 회색 바탕이 됩니다.

## 상태 줄, 건너뛰기 링크, 바닥글, 두 열 배치

쓰는 단계: 1-13

### 약속

- 운영 상태 카드의 제목과 배지를 한 줄 양 끝에 둡니다.
- "본문으로 이동"은 평소에 숨겼다가 키보드 초점이 가면 왼쪽 위에 나타납니다.
- 바닥글은 위에 선을 긋고 작은 회색 글자로 씁니다.
- 생산·출고 카드처럼 카드 두 장인 묶음은 같은 폭의 두 열로, 운영 상태 카드 세 장은 넓은 화면에서 한 줄에 놓습니다.
- 두 열은 `repeat(2, minmax(0, 1fr))`로 두고 카드에 `min-width: 0`을 줍니다. 그래프 막대가 12개여도 PC 폭에서 페이지에 가로 스크롤이 생기지 않고 그래프 칸만 밀립니다.
- 영역과 영역 사이, 영역 제목 아래에는 넉넉한 간격을 둡니다.

## 진행 막대, 그래프 자리, 사진 칸

쓰는 단계: 1-13

카드 안의 진행 막대와 시각 글, 그래프 자리, 사진 칸을 꾸밉니다.

### 약속

- 운영 상태 카드의 시각 글은 카드 맨 아래에 붙이고 진행 막대는 카드 폭만큼 길게 합니다.

- 사진 대신 글자가 들어갈 칸도 같은 크기의 점선 상자로 미리 꾸며 둡니다. 지금 화면에는 없는 칸이지만 꾸미기를 꼭 넣습니다.

## 휴대폰 폭 화면

쓰는 단계: 1-14

### 약속

- 폭 700px 이하 규칙을 styles.css (화면을 꾸미는 CSS 파일) 맨 끝에 한 묶음으로 만들고 앞으로 휴대폰 규칙은 이 묶음에 넣습니다.
- 이 폭에서는 좌우 여백을 줄이고 로고를 조금 작게 하며 "관제 대시보드"를 "텀블공장" 아래 줄에 둡니다.
- 알림 버튼은 글자를 숨기고 종 아이콘만 머리 부분 오른쪽 위에 둡니다. 기준 시각 선택 상자와 조회 상태는 로고 아래 줄에, 새로고침 버튼과 다음 조회 글자는 그 아래 줄에 놓습니다.
- 카드 묶음을 모두 한 열로 하고 카드 안 여백과 영역 간격을 조금 줄입니다.
- 생산·출고 수량 글자 크기는 바꾸지 않고 폭 375px에서 가로 스크롤이 생기지 않게 합니다.

## 만들지 않는 것

기본으로 만들지 않는 기능입니다. 사용자가 만들어 달라고 하면 완료 브랜치 코드를 보고 만듭니다.

- 움직임 줄이기 설정(`prefers-reduced-motion: reduce`)에서 버튼 눌림, 도는 아이콘, 버튼 색 바뀜 효과를 끄는 규칙: 혼자 쓰는 연습용 웹 서비스라 만들지 않습니다.
- 중간 폭 화면(701~1199px)에서 머리 부분 오른쪽 묶음을 로고 아래 줄로 내리고 701~850px에서 운영 상태 카드를 두 열로 놓는 규칙: 화면 꾸밈 세부라 만들지 않습니다.
- 아래로 스크롤해도 머리 부분이 화면 위에 붙어 있게 하는 머리 부분 고정(`position: sticky`): 화면 꾸밈 세부라 만들지 않습니다.
